# Minecraft Server Docker Setup

Docker-конфигурация для запуска Minecraft сервера (Vanilla, Forge, CurseForge модпаки) на основе образа [itzg/minecraft-server](https://github.com/itzg/docker-minecraft-server) с веб-панелью управления, BlueMap и веб-консолью.

## Требования

- Docker (версия 20.10 или выше)
- Docker Compose (версия 2.0 или выше)
- Минимум 2GB свободной RAM (рекомендуется 4GB+ для модпаков)
- Минимум 10GB свободного места на диске

### Зависимости веб-панели

Веб-панель использует следующие Python библиотеки (устанавливаются автоматически):

- **flask** (>=2.3.0) - веб-фреймворк
- **flask-cors** (>=4.0.0) - поддержка CORS
- **psutil** (>=5.9.0) - мониторинг системных ресурсов
- **requests** (>=2.31.0) - HTTP запросы
- **docker** (>=6.1.0) - Docker API для получения логов и статистики

Все зависимости указаны в `web-admin/requirements.txt` и устанавливаются автоматически при сборке Docker образа.

## Быстрый старт

1. **Клонируйте или скачайте проект**

2. **Настройте конфигурацию сервера** (опционально):
   ```bash
   # После первого запуска отредактируйте ./data/${SERVER_DATA_DIR}/server.properties для настройки сервера
   # EULA принимается автоматически, дополнительная настройка не требуется
   ```

3. **Настройте переменные окружения** (опционально):
   ```bash
   cp env.example .env
   ```

   ```bash

   ```

## Настройка

### Режимы работы сервера

Проект поддерживает несколько режимов работы:

1. **Ванильный сервер** (Vanilla) - стандартный Minecraft сервер без модов
2. **Forge сервер** - сервер с модами на базе Forge
3. **Модпак из CurseForge** - сервер с модпаком из CurseForge
4. **Локальный модпак** - автоматическое копирование модпака из папки `modpacks/` при первом запуске

### Переменные окружения

Есть три способа настройки переменных окружения:

#### Способ 1: Использование параметра `--env-file` (без копирования)

```bash
# Для ванильного сервера:
docker compose --env-file env.vanilla.example up -d

# Для модпака (после редактирования env.modpack.example):
docker compose --env-file env.modpack.example up -d
```

#### Способ 2: Копирование примера в .env (рекомендуется)

```bash
# Для ванильного сервера:
cp env.vanilla.example .env

# Для модпака:
cp env.modpack.example .env
# Затем отредактируйте .env и укажите имя файла модпака
```

#### Способ 3: Прямое редактирование .env

Создайте файл `.env` на основе `env.example` и отредактируйте нужные переменные.

**Доступные примеры конфигураций:**
- `env.vanilla.example` - для ванильного сервера
- `env.modpack.example` - для модпака из CurseForge
- `env.example` - полный пример со всеми опциями

**Подробные инструкции:** см. файл `ENV_SWITCH.md`

**Важные переменные:**
- `TYPE` - тип сервера (`CURSEFORGE` для CurseForge модпака, `FORGE` для Forge сервера, пусто для ванильного)
- `MINECRAFT_VERSION` - версия Minecraft (для ванильного сервера)
- `FORGE_VERSION` - версия Forge (для Forge сервера, например: `1.20.1-47.4.13`)
- `MEMORY` - размер памяти для JVM (2G для ванильного, 4G-8G для модпаков)
- `CF_SERVER_MOD` - путь к архиву серверного пакета модпака (только для CurseForge)
- `MODPACK_PATH` - путь к модпаку в папке `modpacks/` (для автоматического копирования при первом запуске)
- `SERVER_DATA_DIR` - имя папки данных сервера (по умолчанию: `vanilla`)
- `RCON_PASSWORD` - пароль для RCON (удаленное управление)
- `ADMIN_PASSWORD` - пароль для веб-панели администратора
- `USE_SPARK_MEMORY` - использовать данные Spark для отображения памяти (true/false, по умолчанию: false)

**Примечание:** EULA принимается автоматически, дополнительная настройка не требуется.

### Установка модпака

Проект поддерживает автоматическое копирование модпака при первом запуске сервера.

#### Способ 1: Автоматическое копирование (рекомендуется)

1. **Поместите модпак в папку `modpacks/`:**
   ```bash
   # Создайте папку modpacks (если её нет)
   mkdir -p modpacks
   
   # Поместите туда распакованный модпак или архив
   # Например, для TerraFirmaGreg:
   cp -r /path/to/TerraFirmaGreg-Modern-0.11.15-serverpack ./modpacks/
   ```

2. **Настройте `.env` файл:**
   ```env
   TYPE=FORGE
   FORGE_VERSION=1.20.1-47.4.13
   MODPACK_PATH=modpacks/TerraFirmaGreg-Modern-0.11.15-serverpack
   SERVER_DATA_DIR=terrafirmagreg
   MEMORY=8G
   ```

3. **Запустите сервер с автоматическим копированием:**
   ```bash
   docker compose --env-file modpack.env up --build
   ```

**Примечание:** Модпак будет автоматически скопирован в папку `./data/${SERVER_DATA_DIR}/` при первом запуске, если целевая папка пуста.

#### Способ 2: CurseForge Server Pack

1. **Скачайте серверный пакет модпака:**
   - Перейдите на [CurseForge](https://www.curseforge.com/minecraft/modpacks)
   - Найдите нужный модпак
   - На странице модпака найдите раздел "Files"
   - Скачайте **Server Pack** (серверный пакет) - обычно это ZIP-архив

2. **Поместите архив в папку `modpacks/`:**
   ```bash
   cp /path/to/server-pack.zip ./modpacks/
   ```

3. **Настройте `.env` файл:**
   ```env
   TYPE=CURSEFORGE
   CF_SERVER_MOD=/data/modpacks/server-pack.zip
   MEMORY=4G  # Увеличьте память для модпака
   ```

4. **Перезапустите сервер:**
   ```bash
   docker compose down
   docker compose up -d
   ```

**Примечание:** При первом запуске с модпаком образ автоматически скачает и установит все необходимые файлы. Это может занять некоторое время.

### Настройка server.properties

Файл `server.properties` находится в директории `./data/${SERVER_DATA_DIR}/` и монтируется в контейнер, что позволяет легко настраивать сервер:

- Отредактируйте `./data/${SERVER_DATA_DIR}/server.properties` напрямую на хосте
- Изменения вступят в силу после перезапуска контейнера
- Основные настройки:
  - `server-port` - порт сервера (по умолчанию: 25565)
  - `gamemode` - режим игры (survival, creative, adventure, spectator)
  - `difficulty` - сложность (peaceful, easy, normal, hard)
  - `max-players` - максимальное количество игроков
  - `online-mode` - проверка лицензий (true/false)
  - `enable-rcon` - включить RCON (true/false, настраивается автоматически)
  - `rcon.port` - порт RCON (по умолчанию: 25575)
  - И многие другие параметры

## Данные сервера

Все данные сервера (мир, конфигурация, моды, логи) хранятся в директории `./data/${SERVER_DATA_DIR}/` на хосте.

### Структура данных:
- `./data/${SERVER_DATA_DIR}/world/` - мир сервера
- `./data/${SERVER_DATA_DIR}/logs/` - логи сервера
- `./data/${SERVER_DATA_DIR}/config/` - конфигурация модов
- `./data/${SERVER_DATA_DIR}/mods/` - установленные моды
- `./data/${SERVER_DATA_DIR}/server.properties` - конфигурация сервера
- `./data/${SERVER_DATA_DIR}/bluemap/` - данные и конфигурация BlueMap

**Примечание:** Папка `data/` игнорируется в Git (см. `.gitignore`), так как содержит пользовательские данные и может быть очень большой.

## Настройка сервера

Файл `server.properties` находится в директории `./data/${SERVER_DATA_DIR}/` и создается автоматически при первом запуске сервера. Вы можете редактировать его напрямую без необходимости заходить в контейнер.

### Основные настройки в server.properties:

- **Игровой режим**: `gamemode=survival` (survival, creative, adventure, spectator)
- **Сложность**: `difficulty=easy` (peaceful, easy, normal, hard)
- **Максимум игроков**: `max-players=20`
- **Порт**: `server-port=25565`
- **Онлайн режим**: `online-mode=true` (проверка лицензий)
- **PvP**: `pvp=true` (разрешить PvP)

После изменения `./data/${SERVER_DATA_DIR}/server.properties` перезапустите сервер:
```bash
docker compose restart minecraft-server
```

## Веб-панель управления

В проекте включена веб-панель управления для администрирования сервера через браузер.

### Доступ к веб-панели:

1. После запуска контейнеров откройте в браузере: `http://localhost:5000`
2. Введите пароль администратора или нажмите "Войти как гость" для просмотра без прав управления
3. Веб-интерфейс подключен к серверу через RCON

### Режимы доступа:

#### Режим администратора
- Полный доступ ко всем функциям
- Выполнение команд через RCON
- Управление игроками (кик, бан, OP)
- Просмотр логов сервера
- Управление пользовательскими командами

#### Гостевой режим
- Просмотр статистики сервера (CPU, RAM, TPS, MSPT)
- Просмотр списка игроков онлайн
- Просмотр карты сервера (BlueMap)
- **Нет доступа** к командам, логам и управлению игроками

### Настройка пароля:

Пароль для доступа к веб-панели настраивается через переменную окружения `ADMIN_PASSWORD` в файле `.env`:

```env
ADMIN_PASSWORD=ваш_безопасный_пароль
```

После изменения перезапустите веб-панель:
```bash
docker compose restart web-admin
```

### Возможности веб-панели:

- **Мониторинг ресурсов сервера:**
  - CPU использование (система и процесс)
  - RAM использование (с приоритетом данных Spark, если доступен)
  - TPS (Ticks Per Second) - производительность сервера
  - MSPT (Milliseconds Per Tick) - время обработки тика
  - Данные обновляются каждые 5 секунд

- **Управление игроками** (только для администраторов):
  - Список игроков онлайн с аватарами
  - Действия с игроками:
    - ⚡ Кикнуть игрока (с указанием причины)
    - 💀 Убить игрока
    - 🚫 Забанить игрока (с указанием причины)
    - ⬆️ Повысить до оператора (op)
    - ⬇️ Понизить (убрать права оператора, deop)
    - Изменение игрового режима (survival, creative, spectator)

- **Консоль сервера** (только для администраторов):
  - Выполнение команд через веб-интерфейс
  - Просмотр ответов сервера в реальном времени
  - История команд (стрелки вверх/вниз для навигации)
  - Вкладка "Команды" для выполнения команд
  - Вкладка "Консоль сервера" с живым потоком логов через ttyd
  - Автообновление логов (каждые 5 секунд)
  - Настройка количества отображаемых строк логов (50, 100, 200, 500)

- **Карта сервера (BlueMap):**
  - Просмотр 3D карты мира в браузере
  - Доступна как администраторам, так и гостям
  - Интегрирована в веб-панель через iframe

- **Быстрые команды** (только для администраторов):
  - Предустановленные команды (Ясная погода, Дождь, Гроза)
  - Создание пользовательских команд с кастомными названиями
  - Удаление пользовательских команд

- **Интеграция со Spark:**
  - Автоматическое получение данных о производительности через Spark мод
  - Отображение TPS, MSPT, CPU и памяти из Spark (если мод установлен)
  - Fallback на Docker stats, если Spark недоступен

### Настройка RCON:

Пароль RCON настраивается через переменную окружения `RCON_PASSWORD` в файле `.env`. При запуске сервера пароль автоматически устанавливается в `server.properties`.

**Рекомендуется:** Используйте надежный пароль для RCON, так как он дает полный доступ к управлению сервером.

После изменения `RCON_PASSWORD` в `.env` перезапустите сервер:
```bash
docker compose restart minecraft-server
```

## BlueMap - 3D карта сервера

Проект включает интеграцию с модом BlueMap для создания интерактивной 3D карты мира Minecraft.

### Доступ к карте:

- **Через веб-панель:** Вкладка "Карта сервера" в веб-панели управления
- **Напрямую:** `http://localhost:25589` (порт можно изменить в `docker-compose.yml`)

### Настройка BlueMap:

Конфигурационные файлы BlueMap находятся в `./data/${SERVER_DATA_DIR}/config/bluemap/`:

- **`core.conf`** - основные настройки (принятие EULA, количество потоков рендеринга)
- **`webapp.conf`** - настройки веб-приложения (язык, тема, стартовая карта)
- **`webserver.conf`** - настройки веб-сервера (порт, webroot)
- **`maps/`** - конфигурация отдельных миров

### Предустановленные настройки:

- **Язык по умолчанию:** Русский
- **Тема:** Темная (по умолчанию в BlueMap)
- **Карта по умолчанию:** Overworld (основной мир)
- **Скрытые миры:** AE2 Spatial Storage (можно включить, отредактировав `maps/world_ae2_spatial_storage.conf`)

### Изменение настроек BlueMap:

1. **Изменить язык:**
   - Отредактируйте `./data/${SERVER_DATA_DIR}/bluemap/web/lang/settings.conf`
   - Измените `default: "ru"` на нужный язык (например, `"en"`)

2. **Изменить карту по умолчанию:**
   - Отредактируйте `./data/${SERVER_DATA_DIR}/config/bluemap/webapp.conf`
   - Измените `start-location: "world"` на нужный мир

3. **Скрыть/показать мир:**
   - Отредактируйте соответствующий файл в `./data/${SERVER_DATA_DIR}/config/bluemap/maps/`
   - Закомментируйте строку `world: "..."` для скрытия мира

4. **Применить изменения:**
   ```bash
   docker exec minecraft-server rcon-cli bluemap reload
   ```

### Проксирование через Nginx (опционально):

Если вы используете домен (например, `minecraft.ridramecraft.ru`), можно настроить Nginx для проксирования:

```nginx
location /map/ {
    proxy_pass http://127.0.0.1:25589/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location /console-live/ {
    proxy_pass http://127.0.0.1:25590/console-live/;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 3600;
    proxy_send_timeout 3600;
}
```

## Веб-консоль (ttyd)

Проект включает веб-консоль на базе ttyd для просмотра логов сервера в реальном времени.

### Доступ к консоли:

- **Через веб-панель:** Вкладка "Консоль сервера" (только для администраторов)
- **Напрямую:** `http://localhost:25590/console-live/` (порт можно изменить в `docker-compose.yml`)

### Особенности:

- Живой поток логов сервера через `docker logs -f`
- Доступен только администраторам через веб-панель
- Автоматический перезапуск при сбоях контейнера

### Запуск консоли отдельно:

```bash
docker compose --env-file modpack.env up -d web-console
```

## Подключение к серверу

По умолчанию сервер доступен на порту `25565`. Для подключения используйте:
- IP адрес вашего сервера: `25565`
- Или локально: `localhost:25565`

## Порты

Проект использует следующие порты:

- **25565** - игровой порт Minecraft (доступен извне)
- **25575** - RCON порт (только внутри Docker сети)
- **25588** - Spark порт (только внутри Docker сети, если используется Spark мод)
- **25589** - BlueMap веб-интерфейс (доступен извне)
- **25590** - Веб-консоль ttyd (доступен извне)
- **5000** - Веб-панель управления (доступна извне)

**Примечание:** Порты можно изменить в файле `docker-compose.yml`, но убедитесь, что BlueMap остается на порту 25589, если вы используете проксирование через Nginx.

## Обновление сервера

### Обновление Minecraft сервера

Для обновления до последней версии:
1. Остановите сервер: `docker compose down`
2. Обновите образ: `docker compose pull minecraft-server`
3. Запустите сервер: `docker compose up -d`

Сервер автоматически загрузит новую версию при первом запуске. Образ [itzg/minecraft-server](https://github.com/itzg/docker-minecraft-server) автоматически определяет и загружает последнюю версию Minecraft.

### Обновление веб-панели

Веб-панель пересобирается автоматически при изменении кода. Для принудительной пересборки:

```bash
docker compose build web-admin
docker compose up -d web-admin
```

### Обновление зависимостей веб-панели

Если были изменены зависимости в `web-admin/requirements.txt`:

```bash
docker compose build --no-cache web-admin
docker compose up -d web-admin
```

## Решение проблем

### Сервер не запускается
- EULA принимается автоматически
- Проверьте логи: `docker compose logs minecraft-server`
- Убедитесь, что файл `server.properties` существует в папке данных сервера (`./data/${SERVER_DATA_DIR}/`)
- Для модпаков проверьте, что указаны правильные `TYPE` и `FORGE_VERSION`
- Проверьте, что модпак скопирован в папку `data/` (если используется автоматическое копирование)

### Порт уже занят
- Измените порт в `docker-compose.yml` (например, `"25566:25565"`)
- Проверьте, что порт 5000 свободен для веб-панели
- Проверьте, что порты 25589 и 25590 свободны для BlueMap и веб-консоли

### Недостаточно памяти
- Увеличьте значение `MEMORY` в `.env` файле
- Убедитесь, что у системы достаточно свободной памяти
- Для модпаков рекомендуется минимум 4GB, для больших модпаков - 8GB+

### Веб-панель не работает
- Проверьте, что контейнер `minecraft-web-admin` запущен: `docker ps`
- Проверьте логи веб-панели: `docker compose logs web-admin`
- Убедитесь, что RCON включен на сервере (`ENABLE_RCON=true`)
- Проверьте, что `RCON_PASSWORD` совпадает в обоих контейнерах
- Убедитесь, что порт 5000 не занят другим приложением

### BlueMap не работает
- Убедитесь, что мод BlueMap установлен в папку `mods/`
- Проверьте логи сервера на наличие ошибок BlueMap
- Убедитесь, что в `core.conf` установлено `accept-download: true`
- Проверьте, что порт 25589 не занят другим приложением
- Выполните перезагрузку BlueMap: `docker exec minecraft-server rcon-cli bluemap reload`

### Веб-консоль не работает
- Проверьте, что контейнер `minecraft-web-console` запущен: `docker ps`
- Проверьте логи консоли: `docker compose logs web-console`
- Убедитесь, что порт 25590 не занят другим приложением
- Перезапустите контейнер: `docker compose restart web-console`

### Ошибки с модпаком
- Убедитесь, что модпак совместим с указанной версией Forge
- Проверьте логи сервера на наличие ошибок загрузки модов
- Для некоторых модов может потребоваться дополнительная настройка JVM аргументов
- Убедитесь, что модпак правильно скопирован в папку `data/`

## Безопасность

- Используется официальный образ [itzg/minecraft-server](https://github.com/itzg/docker-minecraft-server), который запускается от непривилегированного пользователя
- Данные хранятся в volume для персистентности
- Рекомендуется настроить файрвол для ограничения доступа к портам 25565, 25589, 25590
- RCON порт доступен только внутри Docker сети для веб-панели
- Веб-панель защищена паролем (настройте надежный `ADMIN_PASSWORD`)
- Гостевой режим ограничивает доступ к функциям управления
- Рекомендуется изменить пароли по умолчанию (`RCON_PASSWORD` и `ADMIN_PASSWORD`)
- Для production использования рекомендуется использовать HTTPS для веб-панели (через reverse proxy, например nginx)
- BlueMap и веб-консоль доступны без аутентификации - используйте файрвол или reverse proxy для ограничения доступа

## Технические детали

### Архитектура

Проект состоит из четырех основных сервисов:

1. **fix-permissions** - сервис для копирования модпака и исправления прав доступа (запускается один раз при старте)
2. **minecraft-server** - основной сервер Minecraft на базе образа [itzg/minecraft-server](https://github.com/itzg/docker-minecraft-server)
3. **web-admin** - веб-панель управления на Flask
4. **web-console** - веб-консоль на базе ttyd для просмотра логов в реальном времени

### Сеть

Все сервисы работают в изолированной Docker сети `minecraft-network`:
- RCON порт (25575) доступен только внутри сети
- Spark порт (25588) доступен только внутри сети
- Веб-панель (5000) доступна извне для управления
- Игровой порт (25565) доступен извне для подключения игроков
- BlueMap (25589) доступен извне для просмотра карты
- Веб-консоль (25590) доступна извне для просмотра логов

### Файлы конфигурации

- `.dockerignore` - исключения для Docker build (включен в git)
- `.gitignore` - исключения для Git (игнорирует данные, логи, env файлы)
- `docker-compose.yml` - конфигурация всех сервисов
- `env.*.example` - примеры конфигураций для разных типов серверов
